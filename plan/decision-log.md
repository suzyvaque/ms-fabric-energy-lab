# Decision log

| ID | Date | Decision | Why | Alternatives |
|---|---|---|---|---|
| D-001 | 2026-11 | 3 logical workspaces (`ce-fleet`, `ce-asset`, `ce-finance`) × dev/prod; one Git folder per *logical* workspace (`/workspaces/ce-*`); dev and prod share the folder on different branches. | A workspace belongs to exactly one domain, so 3 domains need 3 workspaces. A shared folder means a PR dev → main really promotes items. | Per-environment folders (PRs promote nothing); single workspace (Asset/Finance domains stay empty). |
| D-002 | 2026-11 | Dev workspaces are Fabric Git-synced (`dev` branch). Prod is **not** Git-connected; it is deployed by fabric-cicd from `main`. The `dev` push runs validation only. | Two writers (Git sync + CI/CD) on one workspace drift. fabric-cicd's `parameter.yml` rebinds env-specific IDs; Git sync doesn't. | Git sync on prod (no ID rebinding); both (conflicts). Prod can be Git-connected read-only later as a demo. |
| D-003 | 2026-11 | CI/CD auth = Entra app + GitHub OIDC federated credential per GitHub environment; no client secret. SP scoped via `ce-fabric-automation` group in tenant settings; Contributor on prod workspaces only. | Nothing to rotate or leak; least privilege. | Client secret (rotation burden). |
| D-004 | 2026-11 | Infra scripts = Python wrappers over Fabric CLI / `fab api`, az, gh; tenant values only from `.env`. | Cross-platform, idempotent, same commands as Fabric CLI docs. | Pure Terraform (Fabric provider): good option later for IaC drift detection. |
| D-005 | 2026-11 | Leak guards: gitleaks (pre-commit + CI, required check) + local `private-terms` hook fed from `.env`/`.private-terms.txt` + GitHub push protection. | The public gitleaks config can't list private terms without leaking them. | gitleaks only. |
| D-006 | 2026-11 | Register two OIDC federated credentials per GitHub environment: one name-based, one ID-based (immutable) subject. | New repos present the ID-based subject. ID-based subjects also survive repo or owner renames. | Customize the repo's OIDC subject template via API (one more moving part). |
| D-007 | 2026-11 | Tenant settings are checked by exact `settingName`. Certification is scoped to the admins group. "SP can create workspaces" stays off because the SP only deploys into existing workspaces. | Title keywords matched the wrong settings (e.g. Foundry telemetry for "data agent"). Least privilege. | Keyword matching only. |
| D-008 | 2026-11 | Generator: stdlib Python, one event contract for batch and stream, master data anchored to a fixed date (same seed means same IDs), telemetry landed by *arrival* time, `measurements` as a nested object, schema v2 drift on firmware 2.x, ground truth kept in separate files. | Reproducible demos. Batch history joins live streams. Late, duplicate and drifted data exercise the silver layer (1c). Ground truth lets steps 2 and 7 score detections. | Faker/pandas (heavier, less deterministic); flat columns (no schema-drift lesson). |
| D-009 | 2026-11 | Fleet ingestion = **Eventstream custom endpoint → Eventhouse direct ingestion**. Transformations live in Eventhouse (update policies), not Eventstream operators. Event Hubs stays a documented alternative. | Measured: same p50 (~2 s) below 1 TU; Event Hubs (1 TU) throttled at ~900 events/s (2.4 % loss, retry duplicates) while the custom endpoint had none. About ¼ of the cost (no processor, no Event Hubs). No dependency on SAS policy or a preview connector. See [ingestion-comparison.md](ingestion-comparison.md). | Event Hubs → Eventstream (choose for non-Fabric consumers, replay/Capture, end-to-end private networking). |
| D-010 | 2026-11 | Azure messaging is Entra-only (local/SAS auth off; enforced by policy in this tenant). Producers use `DefaultAzureCredential`; Eventstream reads Event Hubs as the **workspace identity**. | No secrets to store or rotate; matches common enterprise policy. | SAS connection strings (blocked here). |
| D-011 | 2026-11 | Experiments use the `lab_` prefix, stay in dev, and are excluded from prod by `infra/deploy.py` (`item_name_exclude_regex`). | Keeps comparison artifacts reproducible in Git without promoting them. | Separate lab workspace (another domain assignment and Git folder). |
| D-012 | 2026-11 | Eventhouse medallion: bronze = raw envelope + `raw:dynamic` (direct ingestion, streaming); silver via **non-transactional update policies** (normalize v1/v2, flag but keep bad rows); dedup via `take_any` MV (lookback 6h); gold MVs over the dedup MV (store **sums + counts**); a stable "Fleet API" of stored functions is the only contract for dashboards, Activator, agents and the API layer. | Raw replay stays possible; silver never blocks bronze; dedup is exact and cheap within the retry window; additive gold aggregates merge correctly; consumers are insulated from table changes. | Eventstream operators (processor CU); transactional update policies (a bad transform drops bronze); `avgif` MVs (NaN for empty groups). |
| D-013 | 2026-11 | KQL source of truth = `infra/kql/eh_fleet/*.kql`, applied through the KQL DB item definition; Fabric's serialized `DatabaseSchema.kql` (committed from Fabric) is what fabric-cicd deploys. Prod-specific IDs are rebound by `workspaces/ce-fleet/parameter.yml`. | Readable, reviewable KQL; Git integration and CI/CD still use Fabric's own format. | Editing `DatabaseSchema.kql` directly (Fabric reorders and reformats it on commit). |
